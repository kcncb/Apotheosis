# 时间一致的视觉控制链

主程序保留 Media Foundation → NV12/CUDA → TensorRT（或 DirectML）的采集推理底座。目标关联、状态观测、控制输出和设备执行拥有独立的数据边界。

## 数据与时间

- `runtime::FrameContext` 随帧携带采集回调时间、帧序号和图像尺寸。两个推理后端按槽保存并发布这份上下文，不再从全局“最新帧”槽读取来源。
- `DetectionBuffer` 的发布时间与图像采集时间分开。切换模型后，尺寸不匹配的旧检测不会进入控制。
- 准星找色结果使用对应图像的采集时间判断新鲜度；异步处理结束时间不能冒充采集时间。
- 采集回调之前的设备延迟不属于软件探针已测范围。`capture_age_offset_ms` 是明确的模型估计，默认 0 表示未补偿；它不会改变日志里原始采集时间的含义。

## 目标关联与观测

`AimEngine` 仅在新检测到达时运行目标关联和锚点计算。原 AVA 跟踪器保留用于关联候选；其预测框不再作为控制器的新观测。控制器收到的是原始观测框产生的锚点及其真实时间。

自身视角移动会先从关联状态扣除，避免快速拉点时把同一目标误认为另一个目标。短暂丢检后，如果原跟踪仍有效且同类候选通过关联门限，保留目标身份。真正丢失、换目标或锚点类别变化时重置对应状态。

独立的二维位置/速度/加速度观测器使用实际采集时间间隔，扣除观测区间内预计生效的自身指令后，再学习目标运动。框形变会提高观测噪声，降低把框抖动当作目标加速的程度。检测框"位置在跳、面积不变"的抖动不体现在框形变里，只会表现为新息连续变号；而真实换向/急停只变一次号、随后持续同号。因此"机动分支"按连续变号次数区分：连续变号（判为抖动）时把速度归零且不放大速度协方差；只变一次号时仍按原来的因果速度估计处理。否则一次 ±2.5px 的来回抖动会被当成约 600px/s 的速度，并经放大后的速度协方差在随后每帧重新注入（正常路径的速度增益约 1/dt），在锚点附近形成永不收敛的极限环。注意不要改用"按新息幅度抬高观测方差"来抑制抖动：真实的急停/换向同样产生大幅度新息，抬高方差会把本该做的位置吸附一起平滑掉（实测 continuous_tracking_test 的 reverse 场景 p95 会从 4.35px 退化到 14.75px）。X/Y 分别保存状态与协方差。

原 PIDF 参考实现中，两轴共用初始化标志而只初始化第一轴的问题也已修复并保留回归。

## 独立控制时钟

没有新检测时不重复更新观测器。控制输出依据独立节拍，将状态预测到新指令预计生效时刻，并扣除已发送及尚在途的最终位移。

- 接近：较快消除大误差。
- 收敛：根据预计残余误差与相对运动减小输出。
- 跟随：速度前馈加位置修正，避免移动目标进入死区后完全停止跟随。

输出以指令生效区间的中点为目标，兼顾位置误差与预测运动趋势；大模型创新触发短时降阶，位置突跳不被直接外推为持续极端速度。动作生效时间边界有不确定性时，降低对应观测对运动估计的影响。

阶段切换有迟滞。控制器不按丢失的节拍追发一串命令；观测过期时停止输出，短暂缺测时逐步降低预测输出。

Kp/Kd/Kf/LR 的界面字段保留，但现在分别对应阶段位置修正、接近阻尼、速度前馈和观测器响应。它们不再具有旧实现“每帧比例乘 0.1”的解释；相关中文提示已更新。Ki 仍为 0。

## 最终指令与反馈

路径整形保持浮点图像像素，之后统一完成：

1. 像素到鼠标计数的换算。
2. 单次量化与分数余量保存。
3. 最终计数限幅。
4. 进入 `CommandJournal` 并发送。

指令历史记录的是最终接受的计数和对应图像位移，包含 queued/sent/failed/cancelled 状态。覆盖、取消和发送失败不会作为已执行位移进入观测器；发送与取消竞争时，以实际完成的写入记录为准。限幅截掉的位移不会积累为以后必须补发的欠账。

MAKCUNEW 当前只提供串口写入成功，未提供每条移动的硬件执行确认。因此 `sent + effect_delay` 是预计生效时刻，不能称为固件/游戏已执行确认。视觉观测继续修正该模型；硬件执行确认需要后续固件协议支持。

## 硬件映射

「硬件 → 图像与鼠标映射」新增并持久化：

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `mouse_pixels_per_count_x/y` | 当前视角下每个鼠标计数对应的图像像素 | 1.0 |
| `mouse_effect_delay_ms` | 串口发送完成到预计视角响应的延迟 | 8.333333 ms（估计） |
| `mouse_effect_uncertainty_ms` | 上述生效延迟的误差范围（估计） | ±2 ms |
| `capture_age_offset_ms` | 采集回调之前尚未补偿的观测延迟 | 0 ms（未补偿） |

这些默认值不代表本机已完成标定。更改映射或延迟估计会重置控制状态和待发送命令，避免混用两套单位/时间模型。映射应与游戏视角及开镜状态一致；当前没有自动识别开镜倍率。

## 验证边界

`predictive_controller_test` 验证位置接近、恒速运动、双轴对称、帧间隔抖动、丢帧、发送失败、不同正确标定位移倍率、急停/换向、执行延迟估计误差、陈旧/乱序观测和量化限幅。

`aim_engine_test` 编译并调用生产 `AimEngine`，验证目标关联中的自身运动补偿、预测与观测分离、缓存超时、同目标重关联、浮点路径与最终量化，以及包含延迟画面和指令反馈的闭环轨迹。便携测试只用几何类型替身，不包含 OpenCV 图像处理；Windows `ava_chain_test` 使用实际 OpenCV 类型。

`aim_scenario_sim` 保留为旧 PIDF 的参考实验，不代表新生产控制器的效果。新链路以两个新回归入口为准。

逻辑测试不能替代 Windows 主程序编译及采集卡、CUDA、串口、固件、游戏的实机验证，尤其不能证明“任何运动都能零误差锁定”。实机验收应区分首次进入容差、稳定留在容差、过冲、断流停止、切换目标及最终指令执行状态。

本轮完整动程回归与同条件对照见 [连续运动对照](benchmarks/continuous-tracking.md)。
