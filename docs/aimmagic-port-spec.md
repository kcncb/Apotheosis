## 0. 先读这一节：哪些能"直接抄"，哪些绝对不能

| 类别 | 内容 | 能否照抄 |
|---|---|---|
| **① 架构/不变式** | 无死区、连续比例收敛、时间常数形式的微分低通、首拍 D=0、压枪注入点在控制器之后、压枪独立线程用可中断定时等待、换靶不回零 | **✅ 可以直接照抄**，而且应该照抄 |
| **② 代码片段** | 回放循环骨架、采样器余数结转、门控 AND 组合、`move_mode` 合并语义、`_Cnd_wait` 定时等待 | **✅ 可以直接照抄**，这些是纯工程写法，与数值无关 |
| **③ 数值/单位** | `x_kp = 0.1`、`kp_floor = 0.05`、`i_clamp = 6.0`、`max_output = 9999`、`scale_max_move = 9999`、`flick_scale × flick_damping` | **❌ 绝对不能抄**。见 §0.1 |

### 0.1 为什么数值一个都不能抄

**他的 `u = Kp·e + I`，单位是【计数/拍】；你的 `u = dt·Kp·[e + Ki∫e + Kd·d]`，单位是【计数/秒】。**

```
他的 "x_kp = 0.1"        = 0.1 counts / px / 拍
换算成你的单位（120 拍/秒）= 12 counts / px / 秒  ← 才是可比的量
你现在的 Kp_x = 100      = 100 counts / px / 秒
```

**差 8 倍，不是方向相同就能互抄。** 同理：

- 他的 `max_output_x = 9999` 是**每拍**的计数上限；你的 `pidf_limit_x = 0`（内置 200）也是每拍。
  数值看着接近，但他是"限幅默认关（9999 等于不限）"，你是"限幅默认开（200）"——**语义相反**。
- 他的 `i_clamp = 6.0` 是**积分累加器的绝对值上限**（他的积分不乘 dt）；
  你的积分是 `∫e·dt`，单位是【像素·秒】，量纲不同，**不能拿 6.0 当你的上限**。
- 他的 `kp_floor = 0.05`（大误差段的收敛增益）换算过来是 `12 × 0.5 = 6 counts/(px·s)` 量级，
  不是 `0.05`。
- 唯一**可以**直接照搬的量是**时间类参数**：`i_box_lost_hold_ms = 20`、
  `prediction_ms = 12`、`mouse_effect_delay_ms = 8`、`min_hits = 3`、`max_age = 5` —— 
  秒/毫秒/帧是没有单位歧义的。

> **结论**：抄"形状"，不抄"数字"。凡是带 `counts` 或 `px` 量纲的参数，一律按你的单位重算。

### 0.2 这条最要紧：改完必须重新扫增益

你现在的 `config.ini`（`Kp_x=100`、`Kp_y=40`、`deadzone=5`）是**在"有死区 + D 项未滤干净"
这两个约束下反复试出来的折中值**。第 1 件事一改，这两个约束消失：

- 死区去掉 → 末段不再靠"停"来防冲，而是靠增益调度 → **等效回路增益变了**
- D 项时间常数从 6 ms 提到 20~25 ms → **阻尼变了**

**所以旧参数改完就是废的，"感觉不对"不代表移植失败，只代表还没重扫。**
建议流程：先改代码 → 把 `Kp_x`/`Kp_y` 一次性**减半**作为保守起点 → 按 §4 的指标重扫。

## 1. 移植①：无死区 + 连续收敛（治"死区震荡"）

### 1.1 目标形态（照抄它的形状）

```
u = dt · Kp · [ e + Ki·∫e dt + Kd·de/dt ]
      ↑ 无死区：e 多小都要出力，靠连续比例自然收敛
      ↑ 无"停—放"循环：不存在 deadband_active_ 这个状态
```

### 1.2 具体改动（`aim_pid.cpp`）

| 行 | 现在 | 改成 |
|---|---|---|
| `aim_pid.cpp:139-162` | `deadband_active_` 状态机，命中就 `return 0` 并 `carry_ = 0` | **整段删除**（`config.ini` 的 `pidf_deadzone_x/y` 同时设 0） |
| `aim_pid.cpp:18` | `kDerivativeTau = 0.006`（**小于拍间隔，α=0.58 等于没滤**） | `0.020`~`0.025`（≥2.5 倍拍间隔） |
| `aim_pid.cpp:125-129` | `first_` 只初始化 `prev_error_` | 首拍**同时把 `derivative_` 置 0**（照它 `XORPS XMM6,XMM6`） |
| `aim_pid.cpp:231` | `const double p_px = used_error;` | 见下（增益调度） |

**增益调度**（这才是"没有死区也不会冲"的真正原因）：

```cpp
// 新增参数 e_hi（建议 80~120 px，可放 HotkeyProfile 或复用 pidf_* 槽位）
double p_px = used_error;
if (p_sched_e_hi > 0.0) {
    const double a = std::abs(used_error);
    if (a > p_sched_e_hi)
        p_px = std::copysign(p_sched_e_hi, used_error);   // 大误差段饱和，不再线性放大
    // a <= e_hi: 原样透传 ⇒ 小误差段满增益，精度不丢
}
```

注意这与它的 `kp_floor` **补的是相反的一端**（§3.2 已纠正）：
它在**大误差**端切小增益（`|kp_floor| <= |e|` 时 `Kp = kp_floor`），
你在**小误差**端保增益。**两者不冲突，你可以同时要**：
大误差段用连续饱和（比它的二值切换更平滑，没有增益跳变），小误差段满增益。

### 2.3 ⚠️ 一处**不要**照抄：`min_hits = 3` 的门控位置

它的 `min_hits` 作用在**轨迹输出筛选**上，而且它的选靶在**没有稳定轨迹时还有第③级兜底**
（沿用上一拍瞄点）。你如果只加 `min_hits` 而不加第③级兜底，
会出现"目标刚露头 3 帧内完全锁不上"的**反效果**。

**顺序必须是**：先加第③级兜底（沿用上一拍瞄点）→ 再加 `min_hits`。
只做前者是安全的；只做后者会变差。

## 3. 移植③：后坐力控制模块（治"压枪"）

### 3.1 可以直接照抄的代码形状

**弹道步**：`{int rel_x; int rel_y; int delay_ms}`（12 字节）

**线程**（它的 `FUN_14006b630` 回放循环）：

```asm
_Cnd_wait(condvar, mutex)          ; 空闲等唤醒
xchg byte [ready], 0               ; 原子清就绪位
copy vector<step> → 本地快照       ; ★ 快照，不要在持锁状态下遍历
解锁 mutex                          ; ★ 先放锁再发送
for (step : snapshot) {
    if (抢占 || 停止) break;
    emit(step.rel_x, step.rel_y);  ; 发射
    deadline = now + step.delay_ms * 1e6;
    timed_wait(condvar, mutex, ms); ; ★ 可中断的定时等待，不是 Sleep
}
```

**采样器的时间余数结转**（录制不漂移）：

```
acc += (dx, dy); elapsed += Δt;
if (elapsed >= sample_ms) { push({acc, elapsed}); acc = 0; elapsed -= sample_ms; }  // ★ 余数结转
```

### 3.2 五条硬要求（§2.4 已列，这里再钉一遍）

1. **注入点在控制器之后**：累加到 `pending_recoil_x/y`，在 `engine.tick()` 输出之后相加，
   **绝不加进 `err_y`**。它的 `merge` 就是这么做的（`FUN_140067000` 行 1756-1763）。
2. **独立线程 + 绝对截止时刻 + 可中断等待**（`_Cnd_wait` 定时版，不是 `Sleep`）。
3. **自己一条线程按 `start + Σdelay` 走时**，不用检测帧数计时。
4. **默认 `separate`（每步独立发一次），label 区分来源**；要平滑再上 `merge`。
   走 `merge` 必须防"本轮没有新推理导致合并位移被吞"——它靠强制多跑一次瞄准 tick 解决。
5. **门控全 AND + 兜底**：`merge` 但自瞄未激活时**静默退化**为独立发送，不丢位移。

### 3.3 与本项目现有结构的对接点

> **旁证（顺手核对过，与本节无关但值得记一笔）**：反汇编 `pid_core.txt` 行 258-284 显示，
> `XMM12`（前馈项）在 `0x140057300` 处被 `XORPS XMM12,XMM12` **直接清零后参与最终求和**
> （`ADDSD XMM7, XMM12`），而非常量池的 `-125.66370614359172`（`-40π`）确实只作用在
> `XMM8`（微分）路径上 —— 与子代理"微分项走 `1-exp(-40π·dt)`、前馈默认档恒为 0"的结论一致。


| 需求 | 现有可用件 | 缺口 |
|---|---|---|
| 弹道存储 | `HotkeyProfile`（config.h）+ `ConfigBridge` | 需要 schema/default/load/save/bridge/UI 六处对齐 |
| 门控（门控: 右键/自瞄键/有锁定/画面有目标） | `inputDeviceMutex` 之外的按键状态、`engine.lockedTrackId()`、`detections.size()` | 需要统一到一个 gate 函数 |

## 6. 一句话

**① 和 ③ 是"照抄形状、重算数字"；② 是"照抄顺序，别抄门控位置"。**
三件事里唯一不能妥协的是 **③ 的注入点必须在控制器之后** —— 抄错这一条，
压枪会退化成你现在这种"闭环追"，等于白做。
